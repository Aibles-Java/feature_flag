# 2026-08-15 (later session)

## BE fix: unauthenticated returns 401, not 403

The admin chain returned 403 for missing/expired/malformed JWTs — Spring Security's silent
`Http403ForbiddenEntryPoint` default for a chain with no built-in auth mechanism. That broke the
SPA's refresh interceptor, which keys on 401. Added `ProblemDetailAuthenticationEntryPoint`
(401 + `WWW-Authenticate: Bearer` + RFC 7807, coarse detail, MDC requestId).

Nearly shipped a regression with it. The admin chain has no `securityMatcher`, so it also serves
the container's `/error` forward — meaning an unauthenticated `/actuator/**` request, answered by
the management chain with a `Basic` challenge, came back through the admin chain where the header
write replaced it with `Bearer`. Caught by diffing a running instance against develop, not by
reading code and not by the security review. Guarded, and covered by a real-container test after
confirming the MockMvc version passed with the fix removed (i.e. was vacuous).

Security review: no findings at the bar. It did verify the `requestId` now echoed to unauthenticated
callers is sanitised at source and was already exposed via the `X-Request-Id` response header.

`./mvnw verify`: 255 tests green, Spotless + JaCoCo pass.
