
## Session (cont.): implement issue #37 — flag hygiene

- Verified scope against the code first: found `EnvironmentRepository.touchLastUsedAt` +
  `ApiKeyAuthenticationFilter` as an exact precedent for throttled write-on-read, so #37 mirrors it
  rather than inventing a pattern.
- **Caught a would-be production-only bug while writing it:** the SDK evaluation path is
  `@Transactional(readOnly = true)`, so the usage UPDATE joins a read-only transaction — PostgreSQL
  rejects that, H2 allows it. Default propagation would have passed CI and failed in prod. Fixed with
  `REQUIRES_NEW` and pinned by an integration test that asserts real persistence.
- Also deliberate: the touch stays a bulk JPQL UPDATE so `@UpdateTimestamp` does not fire (an entity
  setter would bump `updated_at` on every read); the tracker is called outside any cache-load function
  so a #30 cache hit cannot make hot flags look stale.
- Report is per (flag, environment) pair — staleness is per-environment, and each row's `enabled`
  surfaces the real risk case: an expired flag still on in production. Expiry reports, never disables.
