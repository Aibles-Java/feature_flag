# 2026-08-12

## Issue #38 — environment cloning + flag import/export

Implemented `POST /clone`, `GET /export`, `POST /import` under
`/api/v1/environments/{envId}` in a dedicated `EnvironmentTransferService` /
`EnvironmentTransferController` pair, leaving `EnvironmentService` (the environment
*record*) alone. The export envelope doubles as the import body — the round-trip test
pushes it through real Jackson, so a field rename on either side breaks the build.

Key calls: import derives the project from the path environment and ignores the
snapshot's identifiers (tenancy); it moves state only and never rewrites an existing
flag's project-wide metadata; `dryRun` guards the saves directly rather than leaning on
rollback; `conflictStrategy` defaults to `SKIP`; a clone always mints a fresh API key.
Added `InvalidRequestException` → 400 (the repo had no 400-mapped exception) for bad
`schemaVersion` and duplicate keys. No Liquibase changeset needed — `audit_log.action`
is a bare `VARCHAR(32)`, so the new CLONE/IMPORT audit actions just fit.

`./mvnw verify` green: 276 tests (26 new), Spotless clean, JaCoCo floor met. Committed as
`b637b71`. Noticed but did not fix: `EnvironmentServiceImpl.create()` never backfills
state rows for a project's existing flags — needs its own issue.
