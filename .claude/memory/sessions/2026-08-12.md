# 2026-08-12

## Issue #48 — ArchUnit Tier-1 governance gate

Implemented Track A of the code-graph spec: `archunit-junit5:1.4.2` (test scope) plus
`architecture/ArchitectureTest` with rules R1–R7, gating through Surefire in `./mvnw verify` with
no plugin or CI change. `./mvnw verify` green — 257 tests, Spotless clean, JaCoCo floor met.

The spec's §A.4 code sketch needed three corrections against the current code: R4's
`accessClassesThat()` form doesn't compile on 1.4.2, R1 needs `Security`/`Config` declared as
layers (auth filters legitimately read repositories pre-service), and R4 must allow the whole
`security` package since ArchUnit can't tell a `SecurityContextHolder` read from a write. R7 is
frozen against a committed baseline for the pre-existing `config` ↔ `security` cycle.

Ran the acceptance negative test in both directions and reverted: a controller → repository
reference failed R1+R2 under full `verify`; a fresh package cycle failed the *frozen* R7 without
mutating the store. First attempt at the negative test was a false signal — an injected `private
final` field got swept into Lombok's `@RequiredArgsConstructor` and broke test compilation before
the rule ran.

Shipped as ADR-0004 (issue and spec both say 0003, which pagination already holds) and backfilled
the missing ADR-0003 row in the ADR index.
