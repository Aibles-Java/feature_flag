# 2026-08-15

## Issue #50 — CodeGraphContext MCP spike (Track B)

Installed `codegraphcontext` 0.5.8 into an isolated venv and registered it with Claude Code at
**user scope** — the recorded decision is per-dev, *not* a committed `.mcp.json`, because the server
command is a machine-specific venv path and the working DB backend is OS-dependent.

Three of the spec's Track B setup steps are wrong in practice. The "tree-sitter breaks on Python
3.13" warning is stale (3.13.10 installs fine, 8/8 parsers OK including Java). The real blocker is
one the spec never mentions: FalkorDB Lite cannot install on Windows at any Python version, because
`redislite` has no win32 support — so chasing Python 3.12 would have cost a system-wide install and
still failed. Switched the backend to `kuzudb`. Also `cgc mcp setup` has no Claude Code CLI target,
so registration went through `claude mcp add`.

Validated against grep ground truth rather than eyeballing: `analyze callers requireRole` returned
all 10 production call sites exactly, plus an internal delegation grep would miss. Pinned down the
tool's real limitation — queries are name-keyed, not symbol-keyed, so `getAllFlags` conflates the
controller, the interface and the impl. Navigation aid only; provable-absence stays with ArchUnit.

Recorded as ADR-0005 + memory 0024, and annotated the spec so the next person isn't misled.
